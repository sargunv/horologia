## Exploration Report

### Key Facts

- `server/internal/mcp/gen/tools_gen.go` is **code-generated** by a TypeSpec MCP Go emitter
  (`api/emitters/typespec-mcp-go/src/codegen.ts`). Adding `@mcpTool("name", "desc")` to a `.tsp`
  operation and running `mise run generate` regenerates the `Handlers` interface and `RegisterTools`
  function.
- Currently only 4 tools exist: `task_list`, `task_create`, `task_get`, `task_update` — all from
  `@mcpTool` annotations in `api/src/tasks.tsp`. No other `.tsp` files have `@mcpTool`.
- `*api.Handler` satisfies both `apigen.Handler` (REST) and `mcpgen.Handlers` (MCP) via Go
  structural typing — same methods serve both transports. Adding a method to `Handlers` requires no
  adapter if the handler method already exists on `*api.Handler`.
- **Codegen limitation**: the emitter only handles `Scalar` and `Enum` types for tool params. Arrays
  (`assigneeIds`, `tags`), models (`TaskDue`, `TaskOverdueActionRule`), and `replace` body types
  (array-of-objects like `TaskStatusReplace.items`) are silently skipped.
- `bearerAuthMiddleware` (`mcp/mount.go:40-79`) validates both `session` and `api` tokens, injects
  `auth.User` into context. No MCP-specific scopes exist — any valid token grants access; per-tool
  auth is done by `requireSpaceRead`/`requireSpaceWrite` in the handler methods.
- `requireSpaceRead` (viewer/member/admin) and `requireSpaceWrite` (member/admin) are on `*Handler`
  in `space_access.go:54-61`. Owners bypass membership but space must exist.
- `requireOwner` (`space_access.go:42-51`) gates admin-only ops like `UsersCreate`.
- Handler pattern for writes:
  `h.Pool.Begin → dbgen.New(tx) → operations → activitylog.Log → tx.Commit`. Reads:
  `dbgen.New(h.Pool)` directly.
- Error mapping: `toolResultFromError` extracts `*apigen.ApiErrorStatusCode` message. Void-returning
  ops (deletes) return `mcp.NewToolResultText("ok")`.
- `SpacesList` uses owner-vs-nonowner branching (`ListSpaces` vs `ListSpacesByUser`) — no
  `requireSpaceRead` call, the query itself filters.
- `SpaceMembersList`/`SpaceTagsList` list calls use `requireSpaceRead`; writes use
  `requireSpaceRole(admin)` for members, `requireSpaceWrite` for tags.
- Level replace ops (`SpaceTaskStatuses`, `SpaceTaskEffortLevels`, `SpaceTaskPriorityLevels`) use
  `@put replace` with body `{items: T[]}` — emitter can't handle these due to array body. Level
  lists are simple `@get` with `@path spaceSlug`.
- Activity log has 3 interfaces: `SpaceActivity`, `SpaceTaskActivity`, `UserActivity` — all
  paginated with int64 cursor.
- `Users` interface: `list`, `me`, `get`, `create`, `update`, `delete`. `create`/`list` require
  owner; `me`/`get` check self-or-owner; `update`/`delete` allow self.
- `UserTasks` interface: `list` — cross-space query of tasks assigned to a user, self-or-owner auth.
- `SpaceTaskRelations`: `create` and `delete` — `create` body has `TaskRelationCreate` model (not a
  simple scalar), `delete` takes path params. Relation create would be skipped by emitter due to
  model body.
- MCP test helpers in `mcp_tools_test.go`: `newMCPSession`, `mcpSession.call`, `toolResult`,
  `toolErrorText` — handle SSE/JSON responses.
